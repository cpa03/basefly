## 3. NEW THIS LOOP — Real Code Defect Found & Fixed (Issue #789)

Previous loops (incl. loop200 §3.1) classified #789 as simply **R (resolved)** because `packages/ui/package.json` contains `peerDependencies`. **This loop discovered the resolution left a genuine defect behind:**

### 3.1 The defect

`packages/ui/package.json` contained **two `peerDependencies` keys** (lines 19 and 96):

```json
"peerDependencies": { "react": "^19.0.0", "react-dom": "^19.0.0" },   // line 19 — SHADOWED
...
"peerDependencies": { "next": ">=14.0.0", "react": "^19.0.0", "react-dom": "^19.0.0" }  // line 96 — effective
```

- Duplicate JSON keys are non-standard; most parsers silently keep the **last** occurrence, making the first block dead configuration and a latent defect for strict parsers (e.g., `jsonc-parser`, some bundlers, tooling that iterates keys).
- A monorepo-wide scan (`python3 json.load(object_pairs_hook=...)` over all `**/package.json`) confirmed this is the **only** file with duplicate keys.

### 3.2 The fix (merged)

- Branch `fix/issue-789-duplicate-peer-deps` (from `main`): removed the shadowed first block; kept the complete block (`next`, `react`, `react-dom`).
- Effective resolved value **unchanged** (verified via `json.load` before/after) → zero behavior risk.
- Validated: `json.load` ✅; diff = 4 deletions only.
- **PR #1407** created (labeled `bug` + `P2`), CI cleared, **auto-merged** as squash `4ffa703` on 2026-08-19T07:37Z.
